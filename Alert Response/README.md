Alert Response component (alert record contract v3). The Alert Orchestrator calls `POST /respond` synchronously through a workflow connector; it fills in only `case` and `response`, appends one `trace` entry, and returns the full record. Deterministic, no AI.

**By `triage.disposition`:**
- `SUPPRESS_DUPLICATE` → comment on `triage.matched_case_id`; `case` set to that case; no Slack.
- `DISMISS_KNOWN_GOOD` → create an **open, Info-priority** case tagged `known-good` with the allowlist entry (Triage note + AI Summary action); Slack message to `#security-alerts` noting the Info case, with View case and **Close case** buttons. Close case is a standard interactive Slack button (`action_id: close_case`, `value` = JSON `{case_id, correlation_id}`); the click is handled by the Slack app's interactivity workflow, not here.
- `INVESTIGATE` / `TRIAGE_ERROR` → create a case (tags `dedup:`, `source:`, `severity:`, `verdict:`, `automation-error`; Triage, Enrichment, Investigation, Alert sections), then adds Case Actions (webhook to the Tines case action handler) chosen by source — Sentinel: Get User Details, Revoke Sessions, Force Password Reset, Suspend User; CrowdStrike: Contain Host, Kill Process (when a process is known); every case: Create Slack Channel — and writes the metadata they need (`email`/`username`, `hostname`/`host`/`device_id`, `process_name`/`process_id`/`sha256`); Block Kit to `#security-alerts` with View case and **Assign to Me** buttons and an error warning. Every message for a newly created case (known-good included) has an interactive Assign to Me button (`action_id: assign_to_me`, `value` = JSON `{case_id, correlation_id}`), which the Slack app's interactivity workflow handles by assigning the case to the user who clicked. If verdict is `needs_user_confirmation`, calls Security Reachout `POST /reachout` (expects 202) → `reachout_sent`.

Failures are recorded in `response.errors` and the trace entry `error`; valid input never gets a 500. Invalid input → 400. Alert Triage dedups by searching case tags, so no `/dedup-index` call is made (set `triage_dedup_index_url` to enable it).

Config: `Respond/config.json` (team, channel names). Test: `GET /respond/test` runs `Respond test/sample.json`.
